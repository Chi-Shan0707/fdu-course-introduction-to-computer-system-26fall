# Lec1：Information Represented in Bits

课程主线笔记，整理自课堂讨论（源文件：`tencent_transcript.txt`）。哲学/闲话部分见 `开场闲话.txt`。

## 1. 为什么是二进制（bit）

- 计算机的最小单元是 **bit**，每个 bit 只有两种可能性：0 或 1。
- 8 个 bit 组成 1 **byte**。
- 课堂讨论了"为什么不用三进制"：
  - 电路角度：低电平 = 0，高电平 = 1，两态最直观、最容易用硬件（晶体管/继电器）实现。
  - 历史角度：纸带只有"打孔/不打孔"两种状态，天然对应二进制。
  - 工程角度：二进制对应的布尔代数（与/或/非门）体系简单、成本低、易于迭代；三进制需要重新设计整套代数体系。
  - 结论：没有绝对"正确"答案，是历史和工程权衡的结果（历史上苏联确实做过三进制计算机 Setun）。

## 2. 数制转换

- **十进制 → 二进制**：除二取余，逆序排列。
  例：34 → 100010（34÷2=17余0，17÷2=8余1，8÷2=4余0，4÷2=2余0，2÷2=1余0，1）
- **二进制 → 十进制**：按位权展开，Σ(bit × 2^i)。
- 通用 K 进制展开式：数值 = Σ dᵢ × Kⁱ（dᵢ 为该位系数，K 为进制基数）。
- 小数部分转二进制：不断乘二取整数部分，直到出现循环或结束。
  例：0.3 → 0.0100110011...（循环小数，永远无法精确表示）。

## 3. 逻辑门与加法器

- 基本逻辑门：**与(AND)、或(OR)、非(NOT)、异或(XOR)**。
  - AND：两个输入都为1才输出1。
  - OR：任一输入为1即输出1。
  - NOT：取反。
  - XOR：两个输入不同则输出1，相同则输出0。
- **异或门可由与、或、非门组合实现**：`(A AND NOT B) OR (NOT A AND B)`。
- **一位全加器**：
  - 和位 = A XOR B
  - 进位 = A AND B
- **多位加法器**：将每一位的异或结果、进位结果通过链式连接（低位进位输入到高位），从而拼接成 32 位、64 位加法器——本质就是"用与或非门 + 导线"搭出来的电路。

## 4. 有符号整数表示：补码 (Two's Complement)

设计目标：找到一种表示负数的方式，使其能**复用已有的加法器电路**，即要求 `X + (-X) = 0`（在该位宽下溢出归零）。

- 简单的"符号位+绝对值"方案的问题：
  - 加法逻辑不能直接复用普通加法器（正负数混合相加结果不对）。
  - 存在两个"零"（+0 和 -0），冗余且需要额外判断。
- **补码的推导过程**：
  - 若要 `X + (-X) = 0`（mod 2ⁿ），即 `-X = 0 - X`。
  - `0 - X` 等价于 `全1 - X + 1`（因为全1 = 2ⁿ - 1）。
  - `全1 - X` 恰好等于把 X 的每一位取反。
  - 所以 `-X = 取反(X) + 1`，即**取反加一**。
- **数学解释**（书上写法）：把最高位的位权从 `+2ⁿ⁻¹` 改成 `-2ⁿ⁻¹`，其余位权不变，即可自然得到有符号数的效果。
- 补码的性质（以 32 位为例）：
  - 最大正数：`0111...1` = 2³¹ - 1
  - 最小负数：`1000...0` = -2³¹
  - -1 表示为全 1：`1111...1`
  - 0 表示唯一：全 0
  - 补码下比较大小、做加法，可以直接复用无符号数的电路逻辑（只是最高位的含义/权重不同）。

### 溢出的现实危害
- 无符号数溢出案例：《文明》(Civilization) 游戏中"侵略值"用 8 位无符号数存储（范围 0–255），印度文明升级导致数值下溢（1 - 2 → 255），造成"文明等级越高突然疯狂扩张"的经典 bug。
- 说明：理解有符号/无符号数的表示范围和溢出行为，在实际工程（如航空、高铁控制系统）中至关重要。

## 5. 浮点数表示 (IEEE 754)

### 5.1 设计动机与矛盾
设计一个能装进 32 位的小数表示法，需要同时满足两个互相矛盾的目标：
- **精度高**（小数部分位数越多越好）
- **表示范围大**（能表示很大的数，也能表示很接近 0 的数）

这两者对存储位数是此消彼长的关系——32 位是固定的，多分给精度就少分给范围，反之亦然。

### 5.2 科学计数法思路
- 任何非零二进制数都可以写成 `1.xxxxx × 2^E` 的形式（首位必为1）。
- 既然首位恒为1，可以省去不存，只存小数部分（尾数/fraction）。
- 例：12.3 (十进制) = 1100.01001... (二进制) = `1.10001001... × 2³`

### 5.3 IEEE 754 格式（I-triple-E，非 "I-E-E-E"）

任何数可表示为：
```
value = (-1)^S × M × 2^E
```
- **S (sign bit)**：符号位，0为正，1为负。
- **M (significand/尾数)**：1.0 ≤ M < 2.0 的小数（normalized 情况下省略隐含的前导1）。
- **E (exponent)**：真实指数，通过 EXP 字段编码（带 bias 偏移）存储。

位宽分配：
| 类型 | 总位数 | Sign | Exp | Fraction |
|------|--------|------|-----|----------|
| float (单精度) | 32 | 1 | 8 | 23 |
| double (双精度) | 64 | 1 | 11 | 52 |

### 5.4 Normalized（规格化）情况
- 条件：EXP 字段既不全 0 也不全 1。
- 单精度 bias = 127，双精度 bias = 1023。
- 真实指数 `E = EXP - bias`。
- 单精度可表示指数范围：EXP ∈ [1, 254] → E ∈ [-126, 127]。
- 尾数 M = 1.fraction（隐含前导1）。

推导出的关键边界值（单精度）：
- 最大正数 ≈ (2 - 2⁻²³) × 2¹²⁷ = 2¹²⁸ - 2¹⁰⁴
- 最小规格化正数 = 1.0 × 2⁻¹²⁶
- 精度间隔（ULP）随指数变化而变化。

### 5.5 Denormalized（非规格化）情况
- 条件：EXP 字段全 0。
- 此时 E = 1 - bias（固定为最小指数），尾数不再有隐含前导1，M = 0.fraction。
- 目的：填补 0 附近的空隙，让**从最大正数到最小正数（包括0）的所有 bit pattern 按整数顺序单调递增**，使得浮点数比较可以直接复用整数/无符号数的比较逻辑。
- 全 0（EXP=0, fraction=0）表示 0；EXP=0 且 fraction≠0 表示一个非常接近 0 的小数。
- 最小可表示正数（denormalized）= 2⁻¹⁴⁹（单精度）。

### 5.6 舍入 (Rounding)
- 32 位存不下无限循环小数（如 0.3、12.3），必须截断/舍入。
- 一般规则：看被舍去部分是否 > 一半 → 进位；< 一半 → 舍去。
- **恰好等于一半时**：采用"看前一位（保留位的最低位）决定进或不进"的规则（即向偶数舍入 / round-to-even），避免系统性偏差（若总是"逢五进一"，会导致数值整体系统性变大）。
- 现实体现：Excel 中输入 12.3 可能显示为 12.300000...1 之类的精度误差，本质就是浮点数存储的截断误差。

## 6. 关键结论
- 浮点数格式的设计本质是在**精度**与**范围**这对矛盾指标之间做权衡，IEEE 754 通过科学计数法 + 规格化/非规格化双模式 + 偏移指数编码，同时满足了：
  1. 大范围（很大的数和很接近0的数都能表示）
  2. 合理精度
  3. 位模式的单调性（可直接用整数比较逻辑比较浮点数大小）
- 从整数的补码表示到浮点数的 IEEE 754 表示，核心思路都是**先设计好目标，再倒推需要什么样的编码规则**，而不是死记硬背公式。

## 7. 单精度极端值速查

| # | 名称 | 32-bit pattern | Hex | Approx. value |
|---|------|---------------|-----|---------------|
| A | 最大正有限值 | `0 11111110 111...1` | `0x7F7FFFFF` | ≈ +3.40×10³⁸ |
| B | 最小规格化正数 | `0 00000001 000...0` | `0x00800000` | ≈ +1.18×10⁻³⁸ |
| C | 最小非规格化正数 | `0 00000000 000...1` | `0x00000001` | ≈ +1.40×10⁻⁴⁵ |
| D | 最大负值（绝对值最大） | `1 11111110 111...1` | `0xFF7FFFFF` | ≈ -3.40×10³⁸ |
| E | 负数中最接近0（规格化） | `1 00000001 000...0` | `0x80800000` | ≈ -1.18×10⁻³⁸ |
| F | 负数中最接近0（非规格化） | `1 00000000 000...1` | `0x80000001` | ≈ -1.40×10⁻⁴⁵ |

**Case A 推导：** `0 11111110 111...1` → E=254-127=+127, M=2-2⁻²³ → (2-2⁻²³)×2¹²⁷ = 2¹²⁸-2¹⁰⁴ ≈ 3.4028×10³⁸。E=11111111 保留给 Inf/NaN。

**Case C 推导：** E=0 时规则变化，隐含位变为 `0.`，真实指数固定为 -126（不是 0-127=-127）。M=2⁻²³，值=2⁻²³×2⁻¹²⁶=2⁻¹⁴⁹ ≈ 1.40×10⁻⁴⁵。这是离0最近的正数，再小就是 +0。

最大非规格化数 `0 00000000 111...1` = (1-2⁻²³)×2⁻¹²⁶ ≈ 1.175×10⁻³⁸，恰好比 Case B 小一点——这就是 gradual underflow。

## 8. 特殊值：0, Inf, NaN

- **Exp=全1, Fraction=0** → ±Inf（溢出）
- **Exp=全1, Fraction≠0** → NaN（如 √(-1)）
- **Exp=全0, Fraction=0** → ±0
- **Exp=全0, Fraction≠0** → 非规格化数（见 Case C/F）

## 9. 浮点数运算原理

### 加减法
1. **对齐：** 对较小指数的数右移其尾数，使两数指数一致
2. **整数加法：** 尾数直接送入补码加法器
3. **规格化：** 结果重新调整为 1.xxx 格式

⚠️ **灾难性抵消：** 两相近数相减，有效位大量丢失，精度骤降。

### 乘除法
- 乘：尾数相乘，指数相加（减一次 bias）
- 除：尾数相除，指数相减（加一次 bias）

### 超越函数（eˣ, ln x, sin, cos）
- **eˣ：** 利用 eˣ = 2^(x/ln2)，整数部分直接加到 E 字段（快速整数加法！），小数部分用 minimax 多项式近似
- **ln x：** ln(x) = ln(1.F) + (E-Bias)·ln(2)，整数部分直接提取，只用多项式近似 ln(1.F)
- **sin/cos：** 1) Range reduction（模 π/2，需高精度 π 值如 Payne-Hanek 算法）；2) 多项式近似（FMA 指令）

## 10. 补充：补码 vs 偏移指数 & 十六进制

### 为什么整数用补码？
- **统一加减法：** A - B = A + (B的补码)，ALU 只需一套加法器
- **乘除器也复用：** 部分积阵列+Booth 编码，原码乘法器稍作改造即可处理补码
- **唯一零：** +0 和 -0 无区别，避免 `if (x==0)` bug

### 为什么用十六进制读内存？
- 16 = 2⁴，**4 bit ↔ 1 hex char** 完美映射
- `0x40490FDB` 比 32 位二进制串可读性高得多
- 十六进制不是新数制，只是人类可读的二进制缩写
